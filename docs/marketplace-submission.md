# Marketplace submission handoff

Sources checked: [publishing guide](https://plugins.omarchy.org/publish.html),
[issue form](https://github.com/omacom/omarchy-plugin-marketplace/blob/main/.github/ISSUE_TEMPLATE/submit-plugin.yml),
and [`inspectPluginManifests`](https://github.com/omacom/omarchy-plugin-marketplace/blob/main/scripts/build-catalog.mjs).
Recheck them before submitting; marketplace policy can change.

## Requirements

- Public GitHub repository, root README and license, safe documented install and removal.
- Exactly **one** root `manifest.json` for new submissions. The current validator
  discovers root and one-level nested manifests and rejects multiple manifests;
  a second `omarchy-plugin/manifest.json` would cause `unsupported-repository-layout`.
- Required manifest fields: `schemaVersion`, `id`, `name`, `version`, `author`,
  `description`, `kinds`, `entryPoints`. Version has a 64-character marketplace
  display limit. Entry-point files must exist and pass Quattro compatibility.
- Preview is optional; omitted here to avoid publishing private desktop content.
  The marketplace uses its fallback preview.
- The submitted current commit is validated automatically before maintainer
  approval. Listing approval does not constitute a security review.

The installed Omarchy CLI accepts root entry point
`omarchy-plugin/BarWidget.qml`. A legacy flattened-copy manifest is generated by
`install.sh` instead of being checked in as a duplicate.

### Maintainer notes

Read-only Mercedes-Benz state-of-charge, electric-range and charging widget.
Root manifest loads `omarchy-plugin/BarWidget.qml`. Requires a separately installed
Python 3.9+ connector (build and runtime dependencies are pinned transitively in
`requirements.lock` / `build.lock`, installed with hash enforcement),
a compatible connected Mercedes account/vehicle and user-performed interactive
browser login. The recommended setup uses a venv outside the plugin checkout and
an explicitly installed systemd user service (or a foreground daemon).
Omarchy add/update/remove only manages the widget checkout; it runs no setup hooks.
The English README documents separate connector installation, update, removal,
retained credentials, privacy, unofficial API risks, and legacy installer caveats.
No vehicle commands or intermediary analytics/cloud service. No preview supplied.
The bundled electric-vehicle.svg is original neutral silver car-and-battery
artwork released under the project MIT license. No manufacturer logo, emblem or
downloaded brand asset is included. Mercedes-Benz names identify compatibility
only; no trademark rights, affiliation or endorsement are claimed.

## Updating the existing listing (checked 2026-09-24)

This plugin is already listed through marketplace issue #6940. Do not create a
duplicate `[Plugin]` submission. Use the current `verify-plugin.yml` issue form:

- Title prefix: `[Verify]:`
- Verification action: `Verify and publish a newer upstream commit`
- Plugin ID: `hendkai.omarchy-mercedes`
- Repository URL: `https://github.com/hendkai/omarchy-mercedes`
- Target commit: the full 40-character **current default-branch HEAD** after merge.
- Acknowledge that verification applies only to that exact snapshot and is not a
  security audit.
- Do **not** request standard installation or claim no manual setup: the Python
  connector, account login and user service still require explicit setup.

Source: marketplace `.github/ISSUE_TEMPLATE/verify-plugin.yml` and
`.github/workflows/validate-plugin-update.yml`. The update workflow validates
an immutable SHA and runs a new security baseline before guarded promotion.
The new pairing action launches the local CLI in a terminal and can restart
an already-active user service after successful login. Disclose this capability
in update notes; do not self-apply maintainer approval/security labels.

Plugin and connector update independently. Mention both README update paths in
the release notes. Do not publish private callback URLs, tokens, VINs, screenshots
or vehicle data as review evidence. Keep interrupted tests explicitly unpassed.

## Local verification commands

```sh
omarchy plugin validate .
PYTHON_KEYRING_BACKEND=keyring.backends.null.Keyring /usr/bin/python3 -m unittest discover -s tests -v
bash -n install.sh uninstall.sh tests/check_marketplace_setup.sh
bash tests/check_marketplace_setup.sh
```

The setup test builds and installs the real package in a temporary HOME, checks
CLI provenance/version and Waybar JSON, checks refusal to overwrite existing CLI
and service targets, upgrades, and removes code while retaining synthetic data.
It never starts a service or daemon, logs in, or accesses real credentials.
Remote marketplace validation and hosted CI remain pending until the reviewed
commit is pushed; local structural success is not remote listing approval.
